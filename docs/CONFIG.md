# 后台配置

初始化之后，后台里那些开关分别是干什么的。

> 从 [README](../README.md) 拆出来的详细说明。

## 后台初始化

首次启动时系统没有任何管理员，访问任意页面都会跳转到 `/setup`。

- 用户名 3–32 位
- 密码 **≥ 8 位，且至少包含字母 / 数字 / 符号中的两类**
- `admin`、`123456`、`password` 等常见弱口令会被直接拒绝

> 系统**不预置任何默认账号密码**。这是刻意的 —— 预置 `admin/admin` 的系统在互联网上活不过一天。

也可以用命令行创建：

```bash
docker compose exec moecard /app/moecard-migrate -create-admin -u yourname -p 'YourStrongPass!23'
```

初始化后建议立刻完成三件事：

1. **商城设置** —— 商城名称、公告、联系方式、时区、订单超时时间
2. **邮件配置** —— 配好 SMTP 并发送测试邮件（否则买家收不到卡密）
3. **支付方式** —— 添加至少一个支付渠道并点「测试」

## SMTP 配置

后台 → **邮件配置**。常用服务商已内置一键预设。

| 服务商 | 主机 | 端口 | 加密 | 备注 |
|---|---|---|---|---|
| QQ 邮箱 | smtp.qq.com | 465 | SSL | 用**授权码**，不是登录密码 |
| 163 邮箱 | smtp.163.com | 465 | SSL | 用**授权码** |
| Gmail | smtp.gmail.com | 587 | STARTTLS | 用应用专用密码 |
| Outlook | smtp.office365.com | 587 | STARTTLS | |
| Resend | smtp.resend.com | 465 | SSL | |
| SendGrid | smtp.sendgrid.net | 587 | STARTTLS | 用户名固定 `apikey` |

**发件人邮箱通常必须与 SMTP 用户名一致**，否则会被服务商拒绝。

支持三套模板（自动发货 / 手动发货 / 支付成功），可用变量见页面下方（点击即插入）。

> 📌 **邮件发送与支付流程完全解耦**。发送失败不会影响订单与发货，
> 只会记录在「系统日志 → 邮件日志」中，可随时在订单详情里重发。

## 商家通知

后台 →「商家通知」。解决的问题：手动发货订单进来、卡密卖光、订单收了钱却发不出货 ——
这些都需要你立刻介入，但在此之前只能靠主动登后台刷新才能发现。

支持四种渠道，可同时启用多个：

| 渠道 | 怎么配 |
|---|---|
| Telegram | 向 [@BotFather](https://t.me/BotFather) 申请机器人拿 Token；把机器人拉进群后访问 `https://api.telegram.org/bot<Token>/getUpdates` 看 chat_id |
| Bark（iOS） | 装 Bark App，复制首页那串推送地址 |
| 企业微信 | 群里「添加群机器人」，复制 Webhook 地址 |
| 自定义 Webhook | POST + JSON 推到你自己的地址；配了密钥会带 `X-MoeCard-Signature`（HMAC-SHA256，签名对象是原始请求体） |

可推送的事件（默认只开真正需要你动手的三个）：

- **待人工发货** — 手动发货商品付款后立即提醒
- **订单需要处理** — 买家已付款但系统发不出货（缺货、商品被删）
- **库存告急** — 卡密低于阈值。每 15 分钟扫描一次，同一商品只提醒一次，补货后才重置
- 订单退款 / 每笔订单支付成功（单量大时会很吵，默认关）

通知失败**绝不影响**订单与发货，失败记录在「系统日志 → 通知日志」里。

## 买家自定义信息

代充、账号租赁这类手动发货商品，光有邮箱是发不了货的 —— 你得知道买家的游戏账号。

后台编辑商品 →「下单时需要买家填写的信息」，最多加 5 个字段：

- 类型：单行文本 / 多行文本 / 下拉选择
- 可设必填、输入提示、正则校验（如游戏 ID 限定 `^[0-9]{6,12}$`）

买家在下单页填写，内容随订单存储，在后台订单详情里高亮展示并可一键复制，
导出 CSV 时也会带上。定义之外的字段一律丢弃，买家无法往订单里塞任意数据。

## 卡密静态加密

默认不开启（向后兼容）。开启后卡密内容与两步验证密钥都会 AES-256-GCM 加密后再落库。

```bash
# .env
DATA_ENCRYPTION_KEY=$(openssl rand -hex 32)
```

已经运行过一段时间的实例，执行一次即可加密历史数据（幂等，可重复执行）：

```bash
MoeCard-migrate -encrypt-codes
```

> ⚠️ **密钥必须与数据库分开保管，丢失后已加密的卡密永久无法恢复。**
> 密文带 `enc:v1:` 前缀，与加密前写入的明文数据共存，不影响读取。
> 发货路径上解密失败会让订单转人工处理，绝不会把密文当卡密发给买家。

## 后台两步验证

后台 →「管理员」→「两步验证」。用任意验证器 App（Google Authenticator、1Password、Authy）
扫码即可，标准 TOTP（SHA-1 / 6 位 / 30 秒）。

- 开启时会生成 **8 个一次性恢复码**，只显示这一次 —— 手机丢了靠它进后台
- 开启会作废所有已登录会话，需要重新登录
- 关闭需要输入当前密码（只验证码不够：手机被拿到就能直接关掉）

## 备份与导出

```bash
# 一致性快照备份（SQLite）。用 VACUUM INTO，不是 cp ——
# WAL 模式下直接拷文件会得到一个撕裂的中间状态
MoeCard-migrate -backup
MoeCard-migrate -backup -backup-to /path/to/backup.db

# MySQL 用 mysqldump
mysqldump -h主机 -u用户 -p 数据库名 > backup.sql
```

后台「订单管理」「卡密管理」都有**导出 CSV**按钮，按当前筛选条件导出，
带 UTF-8 BOM（Excel 直接打开不乱码），大数据量分批流式写出不会打爆内存。
