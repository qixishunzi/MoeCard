## 常见问题

<details>
<summary><b>用户付了钱但订单还是「待支付」</b></summary>

99% 是回调没打进来。排查顺序：

1. 后台 → 系统日志 → 支付日志，看有没有该订单的 `notify` 记录
   - **完全没有记录** → 支付平台压根没请求到我们。检查 `BASE_URL` 是否是公网地址、
     是否已把回调地址填到支付平台后台、防火墙/安全组是否放行
   - **有 `notify_invalid`** → 验签失败。检查密钥是否填错（尤其注意首尾空格、
     私钥换行是否完整）；微信还要检查平台证书是否已轮换
   - **有 `amount_mismatch`** → 回调金额与订单金额不符。检查渠道币种配置
2. 让用户在支付结果页点「立即刷新」，系统会**主动向支付平台查询**作为兜底
3. 确认无误后可在订单详情里手动处理

</details>

<details>
<summary><b>买家没收到卡密邮件</b></summary>

1. 后台 → 系统日志 → **邮件日志**，看该订单的发送记录
   - `failed` → 看 error 列的具体原因（认证失败 / 连接超时 / 被拒收）
   - 没有记录 → 检查「邮件配置」里的开关是否打开
2. 常见原因：
   - QQ/163 邮箱用了登录密码而不是**授权码**
   - 发件人邮箱与 SMTP 用户名不一致，被服务商拒绝
   - 邮件进了买家的垃圾邮件箱
3. 在订单详情点「重发邮件」

> 邮件失败**不影响**订单和发货 —— 买家仍可用订单号 + 邮箱在前台查到卡密。

</details>

<details>
<summary><b>「分类下仍存在商品，不允许删除」</b></summary>

这是有意的保护。点删除时会弹出转移对话框，选择目标分类转移商品后即可删除。
</details>

<details>
<summary><b>自动发货商品的库存怎么改？</b></summary>

自动发货商品的库存 = **未使用卡密的数量**，不能直接改数字。
去「商品管理 → 卡密」导入或删除卡密即可。

这样设计是为了避免两个库存来源打架 —— 如果既能改数字又有卡密表，
必然出现「库存显示 10 但只有 3 张卡密」的情况。
</details>

<details>
<summary><b>订单一直卡在「待发货」</b></summary>

- **手动发货商品**：这是正常状态，去订单详情点「填写发货内容」
- **自动发货商品**：说明发货时出了问题，订单会被标记为**异常**（Dashboard 有红色告警）。
  最常见的原因是「订单过期后支付回调才到，此时卡密已被别人买走」。
  补充卡密后手动发货即可。

系统**绝不会**因为无货就吞掉已收到的钱 —— 一定会留下订单和异常记录。
</details>

<details>
<summary><b>忘记管理员密码</b></summary>

```bash
docker compose exec moecard /app/moecard-migrate -create-admin -u newadmin -p 'NewStrongPass!23'
```

用新账号登录后，去「管理员」页面重置或删除旧账号。
</details>

<details>
<summary><b>能不能多实例 / 多副本部署？</b></summary>

可以，但**必须改用 MySQL**。SQLite 只支持单进程写。

多实例时还需注意：限流是内存实现的（单实例内有效），
多实例部署应在网关层（Nginx `limit_req` / Cloudflare）做统一限流。
</details>

<details>
<summary><b>怎么改商城时区？</b></summary>

后台 → 商城设置 → 时区。

数据库统一存 UTC，时区只影响后台/邮件的时间展示以及「今日成交额」的日期切分。
改时区不会影响已有数据。
</details>

<details>
<summary><b>支付渠道的密钥保存后变成了星号，是不是丢了？</b></summary>

没丢。出于安全考虑，密钥类配置**只在保存时写入，读取时永远返回脱敏值**。
编辑其他字段时不要动它，保存后原值会自动保留。

需要更换密钥时，把脱敏值删掉、填入新值即可。
</details>
